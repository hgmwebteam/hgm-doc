# Industry Acumen check: handoff for the hgmportal build

This folder carries everything Claude Code needs to build the check, the results page and the flashcards on hgmportal.com/dictionary. Put this folder at `reference/industry-acumen-check/` in the hgm-doc repo (next to `reference/sop/`), open Claude Code, and paste the prompt from `PROMPT.md`.

## What's in here

| File | What it is | Who edits it |
|---|---|---|
| `PROMPT.md` | The prompt to paste into Claude Code. | Nobody. It's a one-off. |
| `data/check-bank.json` | The question bank: 61 items covering 90 terms (30 core at 2 points, 60 reference at 1, total 120). Two versions of every question. | Nobody by hand. It's generated by `tools/build_check_bank.py`. |
| `spec/check-flow-decisions.md` | The flow (check → results → flashcards → retake) and the decisions behind it, with dates. | The Claude project. |
| `spec/check-bank-review.md` | The same bank as a readable document, with answers and the open flags. Use it to check the page shows each question correctly. | Generated by `tools/render_review.py`. |
| `tools/build_check_bank.py` | Builds `check-bank.json`. Every numeric answer is calculated from the question's own numbers, and the build fails if a rule is broken (a term missing or doubled, a core term in true/false, a wrong answer key). | Edit here to change a question, then re-run. |
| `tools/render_review.py` | Turns the bank into the review copy. | Rarely. |

The dictionary itself isn't in this folder. The portal already bundles `ref_dictionary-v2-253.json`, and the check reads definitions and call lines from it by slug. If the dictionary changes, update the portal's copy from the Claude project's master. Never edit it in two places.

## How the pieces fit

1. **The dictionary** (already on the portal) is the only place a definition is written.
2. **The bank** holds the questions. Each scored answer points at one dictionary slug.
3. **The page** shows the questions, scores each answer against its slug, and saves the result to Supabase under the person's sign-in.
4. **The results page** lists the slugs you currently have wrong, as the same cards the dictionary uses.
5. **The flashcards** take that list of slugs and show each term's definition from the dictionary.

Because everything hangs off the slug, a wrong answer, a review card and a flashcard always point at the same entry.

## Changing a question later

1. Edit the question in `tools/build_check_bank.py`. Never edit `check-bank.json` directly.
2. Run `python3 tools/build_check_bank.py` from inside `tools/`. If it fails, the message names the rule you broke.
3. Run `python3 tools/render_review.py` to refresh the review copy.
4. Copy the new `check-bank.json` to wherever Claude Code put the bank in the app, and bump `version`.
